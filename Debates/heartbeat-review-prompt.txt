## Code Review: Unix Domain Socket Heartbeat System

### Summary of Changes

A per-repo daemon listens on a Unix domain socket and receives heartbeats from VS Code background tasks. When an IDE window closes, heartbeats stop, and the daemon automatically cleans up the worktree and tmux session. Supporting infrastructure includes socket utilities, diagnostic logging, an optional --visible monitor mode, and 66 tests.

- `.vscode/tasks.json` — Added --visible flag to pick-repo task args

- `test/heartbeat.test.ts` — Updated for seq field in messages
- `test/ide.test.ts` — Added tests for heartbeat task, daemon monitor, visible mode

### Architecture Context

- The daemon runs in a named tmux session (`<repoBasename>_daemon`)
- Socket path: `/tmp/wtsu-<uid>/<sha256(realpath(repoRoot)).slice(0,12)>.sock`
- Heartbeat runs in VS Code integrated terminal (dies when IDE closes)
- Daemon monitor task (`--visible` only) attaches to the daemon tmux session
- Daemon self-shuts down after 60s with no tracked worktrees
