MODULE 8: DAEMON-SERVER (src/daemon-server.ts, test/daemon.test.ts, test/cleanup-logic.test.ts)

Imports: node:net, node:fs, node:child_process, node:path, node:util, node:events, git.ts (isBranchMerged, hasNewCommits, onlyIgnorableChanges, removeWorktreeAndBranch), ide.ts (notifyUser), logger.

Export interface DaemonConfig: { heartbeatTimeoutMs: number, checkIntervalMs: number, idleShutdownMs: number, logger?: Logger }.
Export interface WorktreeState: { lastHeartbeat: number, parentBranch: string, parentCommit: string }.
Export interface DaemonHandle: { server: net.Server, heartbeats: Map<string, WorktreeState>, events: EventEmitter, shutdown: () => void }.

Default config values: heartbeatTimeoutMs 15000, checkIntervalMs 5000, idleShutdownMs 60000.

Export function createDaemonServer(socketPath, repoRoot, config?): creates a net.Server listening on socketPath. On connection: accumulate data in a buffer, split on newlines, JSON.parse each line. For "register" messages: store worktree name with parentBranch, parentCommit, and current timestamp. For "heartbeat" messages: update lastHeartbeat to Date.now(); if worktree not registered, create entry with empty parentBranch and parentCommit. Ignore malformed JSON (catch and continue). Set up setInterval at checkIntervalMs: iterate heartbeats map, if Date.now() - lastHeartbeat > heartbeatTimeoutMs, trigger cleanup for that worktree and delete from map. After cleanup check, if heartbeats.size === 0, track idle time; if idle exceeds idleShutdownMs, call shutdown and emit "idle-shutdown". The shutdown function: clear the interval, close the server, remove socket file (ignore errors). Emit "listening" when server starts, "error" on server error, "cleanup" when evaluating a worktree.

Cleanup logic for a timed-out worktree: (1) Kill tmux session via execFile("tmux", ["kill-session", "-t", worktreeName]); ignore errors. (2) If no parentBranch or no parentCommit: force delete via removeWorktreeAndBranch, return. (3) Check onlyIgnorableChanges on the worktree path (join repoRoot, ".worktrees", worktreeName): if false (has real changes), preserve the worktree and notify user, return. (4) Check hasNewCommits: if false (no new commits), delete via removeWorktreeAndBranch, return. (5) Check isBranchMerged: if true, delete via removeWorktreeAndBranch, return. (6) If not merged, preserve and notify user. (7) Wrap the entire evaluation in try/catch: on error, preserve the worktree (safe default), log the error.

Tests for daemon.test.ts: server starts and emits "listening"; register message stores state; heartbeat message updates timestamp; unregistered heartbeat creates entry with empty parent info; server handles malformed JSON without crashing; idle shutdown triggers after configured time.

Tests for cleanup-logic.test.ts: test all 4 cleanup branches: (a) worktree with uncommitted non-ignorable changes is preserved; (b) worktree with no new commits is deleted; (c) worktree with merged commits is deleted; (d) worktree with unmerged commits is preserved. Also test: cleanup on error preserves worktree; no-parent-info path forces deletion.

CRITICAL IMPLEMENTATION DETAILS

Unix socket communication: all messages are newline-delimited JSON over short-lived connections. Client connects, writes one message + newline, then ends the connection. Server accumulates data per connection in a buffer, splits on newlines, processes each JSON object independently.

Socket path computation: SHA-256 hash of the output of fs/promises realpath(repoRoot), truncated to first 12 hex characters, with .sock extension, in the socket directory.

Heartbeat system: the heartbeat process runs as a VS Code task with runOptions.runOn "folderOpen". When the IDE window closes, VS Code kills the task, which stops heartbeats. The daemon detects the absence of heartbeats (timeout > 15s) and triggers cleanup evaluation.

Conditional cleanup decision tree (in exact order): (1) Kill tmux session for the worktree. (2) If no parent branch/commit info was registered, force-delete the worktree and branch. (3) If there are uncommitted changes outside .claude/ and .vscode/, preserve the worktree and send a macOS notification. (4) If there are no new commits beyond the parent commit, delete the worktree and branch. (5) If the branch is fully merged into the parent branch, delete the worktree and branch. (6) If the branch has unmerged commits, preserve the worktree and send a macOS notification. (7) If any error occurs during evaluation, preserve the worktree (safe default).

All operations that create or modify state must be idempotent. Worktree creation returns existing if path+branch match. Task injection checks labels before adding. Parent task installer checks for existing task label. Daemon startup checks for live daemon via socket before starting.

Error handling philosophy: safe defaults (preserve on error), graceful degradation (socket failures log but don't crash), best-effort side effects (notifications and file logging swallow errors), malformed input tolerance (daemon ignores bad JSON).

Every module function that performs I/O accepts an optional Logger parameter as its last argument. All logging goes through this Logger instance when provided.
